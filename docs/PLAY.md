## Signing

- Upload keystore: `android/.secrets/hush-hall-upload.jks` (alias `upload`), on the Grok Bot box only.
- Passwords: `android/.secrets/keystore.properties` (same folder). The whole `android/.secrets/` folder is gitignored and must never be committed, emailed or pasted in chat.
- **Back up that folder somewhere private** (e.g. a password manager). With Play App Signing a lost upload key can be reset through Play support, but it is slow.
- Upload certificate SHA-256: `80:1A:CD:04:A5:33:8B:64:50:DC:60:A5:41:AD:8A:CB:80:90:9E:51:69:3C:B8:A3:E6:37:79:17:D4:22:DD:BC`

**After the first upload:** Play re-signs the app with its own *app signing key*. Copy that key's SHA-256 from
Play Console -> Test and release -> App integrity -> App signing, and add it as a second entry in
`sha256_cert_fingerprints` in `app/public/.well-known/assetlinks.json`, then redeploy the site. Without it the
Play-installed app shows a browser address bar instead of running full screen.

## Build the AAB / APK

Needs JDK 17 and the Android SDK (platform 35, build-tools 35). On the box both are installed (free):
`source ~/tools/android-env.sh` sets `JAVA_HOME`, `ANDROID_HOME` and `PATH`.

```bash
cd android
echo "sdk.dir=$ANDROID_HOME" > local.properties   # gitignored
./gradlew bundleRelease assembleRelease            # signed with android/.secrets/keystore.properties
# -> app/build/outputs/bundle/release/app-release.aab  (upload this to Play)
# -> app/build/outputs/apk/release/app-release.apk     (for sideloading on a test phone)
```

On another machine: install Android Studio (or the command-line tools + JDK 17), copy `android/.secrets/` next
to the project (or pass `-PhushHallKeystoreProps=/path/to/keystore.properties`), then run the same command.
Without the secrets file the build still works but is unsigned.

Last box build (11 Nov 2026): `android/dist/hush-hall-1.0.0-release.aab` and `.apk` (gitignored), signed with the upload key above.

Quick check on a phone: `adb install android/dist/hush-hall-1.0.0-release.apk`, open Hush Hall, sign in with a magic link.
If the app shows an address bar, Digital Asset Links don't match the signing key (see above).

### Data safety answers (from what the code does; double-check before submitting)

- Collected: **Email address** (account management), **Name**-type data: nickname (app functionality), **App activity / other user-generated content**: study topics, recaps, reports, requests (app functionality, safety), **Audio**: voice in study rooms is transmitted live, **not stored** (declare as processed ephemerally, if Play asks).
- Not collected: location, contacts, photos, payment info, device IDs for ads, date of birth (checked, not stored).
- Shared with third parties: no (Supabase, LiveKit and Vercel are service providers acting for Hush Hall).
- Encrypted in transit: yes. People can request deletion: yes (in app and at /delete-account).

## Account deletion (how it works)

- `/me` -> **Delete account** -> "Delete my account…" -> type DELETE -> "Permanently delete my account".
- `POST /api/account/delete` (server only, service key never reaches the browser) drops the person from any live voice call,
  then hard-deletes the Supabase Auth user. `ON DELETE CASCADE` in `supabase/migrations/0001` and `0002` removes the profile,
  sittings and recaps, usual desks, walker row, blocks (both directions), join requests (sent and received), room memberships,
  notices, moderator entry, and reports filed **by** or **about** the person. Rooms they owned keep a null owner (just a room name).
- Choice made: reports about a deleted account are deleted too (true deletion, nothing frozen). The person can no longer use
  Hush Hall, so there is nothing left to moderate; if they sign up again they start with a clean record. If moderators later
  want to keep a redacted record, that needs a schema change and a policy update.
- No new migration is needed: the cascades are already in the live schema. Verified locally with
  `supabase/tests/account_delete_test.sql` (prints `ALL_DELETE_RULES_OK`).
